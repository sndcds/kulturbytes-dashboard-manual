The Event Editor is used to maintain all information belonging to an event on
kulturbytes.

The editor is divided into several pages. Each page contains a specific group of
information. Changes are normally made to the draft and become permanent when
`[ Save ]` is clicked. You can also save your changes using `Ctrl + S` on
Windows/Linux or `⌘ + S` on macOS.


## 1. What

The **What** page contains the central descriptive information about the event.


### Content language

Select the language in which the event content is written.
The content language is important when the event is displayed on kulturbytes and
when content is distributed to other platforms.

Choose the language that best describes the language of the event title and
description.


### Event category

Select one or more categories that describe the general nature of the event.

Categories provide a broad classification and are used to help visitors discover
suitable events.

Select all categories that are genuinely relevant to the event, but avoid
selecting categories only because they might increase visibility.


### Main image

The main image represents the event. It is used as the primary image when the
event is displayed in event lists, search results, detail pages and other
compact views.

Choose an image that clearly represents the event and is suitable for use in
different contexts.

For detailed information about image formats see [Images](../images).

For recommendations on choosing and preparing images, see
[Image best practices](../image-best-practice), including the **do's and don'ts**.


### Title

Enter the official title of the event.

The title should be concise and recognizable. Use the title by which the event
is publicly announced. Suitable event titles should ideally be **no longer than
50 characters**.

Avoid adding dates, venue names or other information that is already provided
separately unless it is actually part of the event title.

You can use the **Title** and **Subtitle** together to provide more information.
Keep the main title short and recognizable, and use the subtitle for additional
details, context or a short description.


### Subtitle

The subtitle provides additional information about the event.
Use it when a short secondary description helps visitors understand the event.
The subtitle should complement the title rather than repeat it.


### Description

The description contains detailed information about the event.

Format the text using the icons above the editor or by typing **Markdown**.
You can use **bold**, *italic*, headings, lists and more.

Provide the information visitors need to understand the event. Include relevant
details such as the names of performers, speakers or artists and what visitors
can expect. The description is also important for search and for AI-based event
classification.

Avoid duplicating information that is already maintained in dedicated fields,
such as date, venue, price or registration information.


### Summary

The summary is a short description of the event. It is used only in compact
views where there is not enough space to display the complete description.

The summary should therefore work as a concise introduction to the event and
should not depend on the visitor reading the full description.

The maximum length is **2,000 characters**.


### Logo

Select which logo should be associated with the event:

* **Organizer** – use the organizer's logo.
* **Venue** – use the venue's logo.

This setting controls which organization is visually associated with the event
in supported displays.


## 2. Where

The **Where** page specifies where the event takes place and whether it is also
available online.


### Venue

Select the venue where the event takes place. The venue can be selected from the
venues available to the organization. If it contains several spaces, you can
optionally select the specific space in which the event takes place.

**Tip:** Learn more about venues and spaces, and when and how to create them,
in [Venues and Spaces](../venue-and-space).


### Meeting point

Use this field when visitors need additional information about where to meet.

For example:

* Main entrance
* Meeting point at the museum courtyard
* Entrance at the rear of the building

Only enter information that is useful in addition to the selected venue.


### Online event

An online event means that participants can take part remotely via a platform
such as Zoom, Jitsi or Teams.

Enter the URL where visitors can access the event. Use a complete URL beginning
with `https://`.

The link is displayed to visitors as the destination for the online event.


## 3. When

The **When** page contains all individual dates on which the event takes place.

An event can have one or several dates. Each date can have its own venue, space,
ticket link and location information.


### Date overview

Each date is displayed as a collapsible card, which shows the start date/time,
optional end date/time, and, if applicable venue and space.

Select a date to open its detailed information.


### Start date/time

Date and time on which the event starts. Both the date and time are required.


### End date/time

Date on which the event ends if the event extends beyond its start date.
For an event taking place on a single day, the end date can remain empty.

Time at which the event ends, when known.


### Entry time

Time at which visitors can enter the event. This is useful when admission starts
before the actual event begins.


### Duration

Duration of the event in minutes when appropriate.


### All-day event

Select **All-day** when visitors can come and go during the event's duration,
without a specific start or end time, for example at an open house.


### Release status

The release status controls the publication state of this particular event date.
A date can override the release status inherited from the event. This makes it
possible, for example, to cancel or otherwise change the publication state of an
individual date without changing the complete event.


### Date-specific ticket link

Use this field when this particular date has a different ticket or booking URL
than the event as a whole.


### Date description

The date description contains information that applies specifically to this date.
Use it for date-specific information rather than duplicating the general event
description.


### Venue

A date can have its own venue and space. This is useful for events that take
place at different locations on different dates.


### Date-specific venue with location

Use this field when a date takes place at a specific location that is not a
regular venue of the organization.

This is useful for one-off locations that are only used for this event date.
Enter the location using latitude and longitude, or select it on the map.


### Adding and removing dates

Select **Add date** to create another event date.

An event must retain at least one date. Additional dates can be removed when
more than one date exists.


## 4. Tags

The **Tags** page describes the event in more detail. This information is
particularly important for search, filtering and event discovery.


### Types and genres

Add one or more **event type and genre combinations**. For each combination,
select an **event type** first and then choose the appropriate **genre**.

The event type describes **what kind of event it is**. The genre provides a
more **specific classification**.

For example:

* **Concert → Folk**
* **Concert → Jazz**
* **Theatre → Musical**

You can add multiple combinations when an event belongs to more than one type
or genre. Use the most specific applicable classifications.


### Languages

Select the languages relevant to the event. This can describe the language in
which the event takes place or the languages that are relevant to visitors.
Only select languages that are genuinely applicable.


### Tags

Tags provide additional keywords that help describe the event. Use tags for
relevant characteristics that are not sufficiently represented by the event type,
genre or categories.

Tags should be meaningful and useful for discovering the event. Avoid adding
large numbers of loosely related keywords.


## 5. Links

The **Links** page contains external links associated with the event.


### Source link

The source link points to the original source of the event information. For
example, this may be the event page on the organizer's website. It allows
visitors and editors to access the original information.

Always use a complete URL beginning with `https://`.


### Event links

Additional links can be added when an event has several relevant web resources.

Each link consists of:

* A short descriptive **title** for the link. It should tell visitors what they
will find when they follow the link (for example Event website, Program, Further information ...)
* A **link type** helping kulturbytes understand and present the purpose of the
external resource.
* The **URL** to the external content beginning with `https://`.

Select **Add link** to add another external resource. Individual links can be
removed when they are no longer relevant.


## 6. Participation

The **Participation** page contains information about who can participate and
whether participation is limited.


### Minimum and maximum age

Enter age limits only when they are relevant to participation.

Enter the **minimum age** when a lower age limit applies. Leave the field empty when there is no minimum age.

Enter the **maximum age** when an upper age limit applies. Leave the field empty when there is no maximum age.


### Maximum number of participants

Enter the maximum number of people who can participate.

This is particularly useful for:

* workshops
* courses
* guided activities
* seminars
* hands-on events

Leave the field empty when participation is not limited.


### Participation information

Use this field for additional information about participation.

For example, you can explain:

* whether prior registration is required
* whether participants need previous knowledge
* whether materials are provided
* whether visitors can participate spontaneously
* whether participation is suitable for specific groups

Do not use this field for general event information that belongs in the event
description.


## 7. Registration

The **Registration** page contains information about registering for the event.
Fill in **only the fields that are relevant to the event**. Leave fields empty
when the corresponding registration option or information does not apply.


### Online registration link

Enter the URL visitors should use to register. Use a complete URL beginning
with `https://`. Leave the field empty if online registration is not available.


### Registration deadline

Enter the last date on which registration is possible. Leave the field empty
when there is no registration deadline.


### Registration email

Enter an email address visitors can use for registration or registration-related
questions. Leave the field empty when no registration email is provided.


### Registration phone

Enter a telephone number visitors can use for registration or
registration-related questions. Leave the field empty when no registration phone
number is provided.


## 8. Ticket

The **Ticket** page contains information about admission and ticketing.


### Price

Enter the minimum and maximum price when the event has a monetary admission fee.
For a single fixed price, only enter the minimum or max price. For events with
different prices, enter the lowest and highest applicable prices.


### Currency

Select the currency in which the price is specified.


### Price type

Select the type that best describes the event's pricing:

* **Not specified:** The price has not been specified.
* **Free:** Participation or admission is free.
* **Donation:** Visitors can participate or attend by making a voluntary donation.
* **Regular price:** The event has a regular admission price.
* **Tiered prices:** Different prices apply depending on the visitor group, ticket type or other conditions.


### Ticket options

The following options can be specified:

* **Advance ticket:** Tickets can be purchased before the event.
* **Presale fee applies:** An additional fee applies when tickets are purchased in advance.
* **On-site ticket sales:** Tickets can also be purchased at the event location.
* **Reduced price available:** Reduced-price tickets are available for eligible visitors.


### Ticket link

Enter the URL where visitors can obtain tickets or find ticket information.
Use a complete URL beginning with `https://`.


## 9. Info

The **Info** page contains additional information that can help visitors decide
whether an event is suitable for them.

Select all applicable characteristics.

This information can be used by kulturbytes to provide better filtering and
accessibility information.

Only select characteristics that actually apply to the event.

The available visitor information options are maintained by kulturbytes and may
be expanded over time.


## 10. Images

The **Images** page contains the images associated with the event. Images can
be used in different contexts and therefore have different formats and purposes.

### Main image

The main image is the primary representation of the event. It is used for event
listings, search results and detail pages.

### Gallery images

Additional gallery images can be added to provide more visual information
about the event. Up to three gallery images are currently available.

Use gallery images when they provide meaningful additional information rather
than simply duplicating the main image.

### Advertisement formats

Several image formats are available for promotional use:

* **1:1** – square format
* **9:16** – vertical format
* **16:9** – horizontal format

These formats can be used when event information is distributed through
different channels that require specific image dimensions.

### Poster

The poster slot is intended for an event poster or flyer. It can contain
substantially more text than a typical event image.


### Instagram image

The Instagram image slot is intended for the `5:4` format used for the
corresponding social-media presentation.

### Image selection

Choose images that:

* represent the event accurately
* are of sufficient quality
* can legally be used for the event
* do not contain misleading information
* remain understandable when displayed at smaller sizes

Where possible, use images that work well both visually and in cropped versions.
